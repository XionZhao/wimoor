## 1. 模块概述

采购记账-转结模块是Wimoor ERP系统中财务管理的核心功能之一，主要用于处理1688账期账户（如"诚e赊"）的采购付款记录与1688平台账单的匹配结转工作。

该模块的核心业务场景是：企业在1688平台使用账期支付方式（如诚e赊）进行采购时，系统会自动记录每笔采购付款。随着时间推移，需要将这些分散的付款记录按照1688平台的账单周期进行"结转"操作，以便将系统内部的付款数据与1688平台的实际账单进行对账和匹配。

### 1.1 适用场景

- **1688账期采购管理**：使用1688诚e赊等账期支付方式进行采购的企业
- **采购付款对账**：需要将系统付款记录与1688平台账单进行对账核验
- **账期还款管理**：跟踪1688账期账户的还款、退款、充退等资金流向
- **采购成本核算**：准确归集和结转采购成本数据

### 1.2 核心价值

- **自动化对账**：将系统付款记录与1688账单自动匹配，减少人工对账工作量
- **资金流向透明**：清晰展示账期账户的付款、还款、退款全流程
- **结转记录可追溯**：每笔结转操作都有完整记录，支持撤销和回溯
- **数据导入支持**：支持导入1688账单明细和批量结转数据

### 2.1 核心功能

| 功能名称 | 功能描述 |
|---------|---------|

## 4. 操作流程详解

### 4.1 账户选择

**功能说明**：页面顶部以卡片形式展示所有账期类型的账户（支付方式为"账期"的账户），用户可以点击切换不同账户。

**操作步骤**：
1. 进入转结页面后，系统自动加载所有账期账户
2. 系统默认选中名称包含"诚e"的账户（如"诚e赊(1688)"）
3. 如需切换账户，点击对应的账户卡片即可
4. 切换后，下方所有区域（采购付款明细、已结转记录、1688账单明细）将自动刷新

**卡片信息说明**：
- **账户名称**：如"诚e赊(1688)"
- **账户标签**：显示"账期"标签，标识该账户为账期支付类型
- **结余金额**：账户当前结余金额

**注意事项**：
- 仅支付方式为"账期"（paymeth=2）的账户会显示在卡片列表中
- 如果没有任何账期账户，页面将不会加载数据

### 4.2 采购付款明细

**功能说明**：展示当前选中账户下未结转的采购付款记录，支持多选、筛选和排序。

**操作步骤**：
1. 选择账期账户后，系统自动加载该账户的未结转付款记录
2. 使用表格上方的筛选条件（日期范围、搜索关键词、仓库、供应商等）进行筛选
3. 勾选需要结转的付款记录（支持全选）
4. 选中的记录数量会实时显示在"结转"按钮上

**筛选条件说明**：
- **日期类型**：可选择按付款日期或其他日期类型筛选
- **日期范围**：设置起止日期
- **搜索关键词**：支持按SKU或订单编号搜索
- **仓库**：按仓库筛选
- **供应商**：按供应商筛选
- **付款方式**：按付款方式筛选
- **收支项目**：按费用类型筛选

### 4.3 结转操作

#### 4.3.1 选择结转

**功能说明**：将用户勾选的特定付款记录进行结转，生成一张结转单。

**操作步骤**：
1. 在"采购付款明细"表格中勾选需要结转的记录
2. 点击"结转(N)"按钮（N为选中数量）
3. 系统弹出确认对话框：`确定要将选中的 N 条付款记录进行结转吗?`
4. 点击"确认"按钮执行结转
5. 结转成功后，系统自动刷新付款明细列表和已结转记录

**注意事项**：
- 必须先勾选至少一条记录，"结转"按钮才可用
- 结转后，被结转的记录从"采购付款明细"中移除，出现在"已结转记录"中
- 结转操作会生成一个结转单号，可在已结转记录中查看

#### 4.3.2 全部结转

**功能说明**：按当前筛选条件，批量结转所有未结转的付款记录。

**操作步骤**：
1. 确保已选择账期账户
2. 可选：设置筛选条件（日期、搜索、仓库等）来限定结转范围
3. 点击"全部结转"按钮
4. 系统先查询当前筛选条件下的未结转记录数量
5. 弹出确认对话框，显示未结转数量并提示"此操作不可撤销"
6. 点击"确认结转"按钮执行批量结转
7. 结转成功后，系统自动刷新相关列表

**注意事项**：
- 全部结转会结转当前筛选条件下的**所有**未结转记录
- 结转前请仔细核对筛选条件，确保范围正确
- 该操作生成的结转单可通过"已结转记录"进行撤销

#### 4.3.3 导入结转

**功能说明**：通过上传Excel文件，根据订单号和SKU自动匹配并生成结转记录。

**操作步骤**：
1. 点击"导入结转"按钮
2. 系统弹出文件上传对话框
3. **下载模板**：点击下载按钮获取Excel模板（模板名称：PurchaseAlibabaSettlement）
4. **准备数据**：
   - 从采购付款明细中导出数据
   - 在Excel中仅保留"订单号"和"SKU"两列
   - 填入需要结转的订单号和SKU信息
5. **上传文件**：选择准备好的Excel文件并上传
6. 系统自动处理导入数据并生成结转记录
7. 导入完成后，系统显示导入结果并刷新已结转记录

**使用说明**：
- 导入模板可从系统下载，路径为 `/erp/api/v1/purchase/alibaba/entry/purchaseAlibabaSettlement/downExcelTemp`
- Excel文件中只需保留订单号和SKU两列数据
- 系统会根据订单号和SKU自动匹配系统中的付款记录并生成结转
- 导入结果会显示成功结转的记录数量

### 4.4 已结转记录管理

**功能说明**：展示历史结转单列表及详情，支持查看详情和撤销操作。

**页面布局**：
- **左侧**：结转单列表（结转单号、关联订单数、结转总金额、操作时间）
- **右侧**：选中结转单的详情信息

#### 4.4.1 查看结转详情

**操作步骤**：
1. 在已结转记录区域，左侧列表展示所有结转单
2. 系统默认选中第一行（最新的结转单）
3. 点击任意一行可查看该结转单的详情
4. 右侧详情面板展示以下信息：
   - 结转单号
   - 结转总金额
   - 操作人
   - 操作时间
   - 关联的付款记录明细表格

**详情表格字段**：
- 订单编号
- 图片
- 名称/SKU
- 供应商
- 采购金额
- 费用类型
- 付款金额（退款以红色标注）
- 操作人
- 备注

#### 4.4.2 撤销结转

**功能说明**：撤销已执行的结转操作，将相关付款记录恢复为未结转状态。

**操作步骤**：
1. 在已结转记录列表中找到需要撤销的结转单
2. 点击该行的"撤销"按钮
3. 系统弹出确认对话框：`确定要撤销结转单吗？撤销后相关付款记录将恢复为未结转状态。`
4. 点击"确认"按钮执行撤销
5. 撤销成功后：
   - 该结转单从列表中移除
   - 相关付款记录恢复到"采购付款明细"中
   - 已结转金额总计自动更新

**注意事项**：
- 撤销后数据不可恢复到结转前状态，但付款记录会重新出现在未结转列表中
- 撤销操作不影响1688账单明细中的数据

### 4.5 1688账单明细

**汇总信息**：

- **确认收货金额**：已确认收货的总金额
- **退款金额**：总退款金额

| 订单支付时间 | 1688平台订单的支付时间 |
| 订单名称 | 1688平台订单的商品名称 |
| 支付金额(元) | 订单实际支付金额 |
| 确认收货金额(元) | 确认收货时的金额 |

**操作说明**：
- 支持按订单编号搜索

| 还款金额(元) | 本次还款金额 |

#### 4.5.3 退款记录

**字段说明**：

| 字段名称 | 说明 |
|---------|------|
| 订单号 | 1688平台退款订单编号 |
| 订单名称 | 退款订单的商品名称 |
| 订单支付金额(元) | 退款订单的原始支付金额 |
| 退款时间 | 退款发生的时间 |
| 退款金额(元) | 实际退款金额 |
| 退款类型 | 退款的分类类型 |
| 退款资金去向 | 退款资金的去向说明 |

#### 4.5.4 充退记录

**功能说明**：展示1688账期账户的充退记录（充值退回）。

**字段说明**：

| 字段名称 | 说明 |
|---------|------|
| 充退时间 | 充退操作的发生时间 |

#### 4.5.5 付款明细

**功能说明**：展示系统中的采购付款记录，与"采购付款明细"区域类似，但此处主要用于与1688账单明细进行对照查看。

**使用场景**：
- 从"账单明细"标签页点击订单号后，自动跳转到此标签页
- 展示该订单在系统中的付款记录详情
- 用于核对系统付款记录与1688账单是否一致

### 4.6 1688账单明细导入

**功能说明**：上传1688平台的账单文件，导入账单明细数据，用于匹配确认收货时间。

**操作步骤**：
1. 在"1688账单明细"区域，点击"1688账单明细导入"按钮
2. 系统弹出文件上传对话框
3. 下载模板（模板名称：PurchaseAlibabaPayDate）
4. 将1688平台导出的账单数据按照模板格式整理
5. 上传文件
6. 系统自动解析并导入账单数据
7. 导入完成后，"账单明细"等标签页将显示导入的数据

**注意事项**：
- 导入后可以在账单明细中搜索买家账单的确认收货时间
- 确认收货时间用于保证系统付款记录与1688账单正确对应
- 导入的数据支持删除操作

## 6. 常见问题与解决方案

### 6.1 无法看到账期账户卡片

**问题**：进入转结页面后，顶部没有显示任何账户卡片。

**原因**：系统中没有配置账期类型的账户（paymeth=2）。

**解决方案**：
1. 进入"概览"标签页，检查是否有账期类型的账户
2. 如没有，点击"添加账户"，创建一个支付方式为"账期"的账户
3. 确保账户名称中包含"诚e"以便默认选中

### 6.2 结转按钮不可点击

**问题**："结转"按钮显示为禁用状态。

**原因**：未勾选任何付款记录。

**解决方案**：
1. 在采购付款明细表格中勾选至少一条记录
2. 勾选后按钮将自动启用并显示选中数量

### 6.3 全部结转提示没有未结转记录

**问题**：点击"全部结转"后，系统提示"当前筛选条件下没有未结转的付款记录"。

**原因**：当前筛选条件下所有付款记录已结转，或筛选条件过于严格。

**解决方案**：
1. 检查筛选条件（日期范围、搜索关键词等）是否正确
2. 尝试扩大日期范围或清除筛选条件
3. 检查"已结转记录"中是否已有全部记录的结转单

### 6.4 导入结转失败

**问题**：上传Excel文件后导入失败或提示错误。

**原因**：Excel文件格式不正确或数据不匹配。

**解决方案**：
1. 确保使用系统提供的模板下载功能获取正确格式
2. 检查Excel中是否只保留了"订单号"和"SKU"两列
3. 确认订单号和SKU与系统中的数据一致
4. 检查Excel文件中是否有空行或格式异常的数据

### 6.5 1688账单明细为空

**问题**：1688账单明细标签页没有数据显示。

**原因**：尚未导入1688平台的账单数据。

**解决方案**：
1. 点击"1688账单明细导入"按钮
2. 下载模板并按照格式整理1688平台导出的账单数据
3. 上传文件完成导入
4. 导入后切换标签页即可查看数据

### 6.6 撤销结转后数据未恢复

**问题**：撤销结转后，付款明细中没有出现恢复的记录。

**原因**：数据刷新延迟或筛选条件导致记录被隐藏。

**解决方案**：
1. 等待几秒钟后手动刷新页面
2. 检查采购付款明细的筛选条件是否过于严格
3. 尝试清除筛选条件后重新查询

### 6.7 账单明细中订单号点击无反应

**问题**：在"账单明细"标签页点击订单号后没有跳转。

**原因**：系统付款明细中没有该订单的对应记录。

**解决方案**：
1. 检查订单号是否正确
2. 确认该订单在系统中是否有采购付款记录
3. 检查付款明细标签页是否正确加载

## 7. 注意事项

### 7.1 业务规则

- **仅账期账户可用**：转结功能仅对支付方式为"账期"（paymeth=2）的账户开放
- **结转单不可直接编辑**：结转单一旦生成，不可直接修改，只能通过撤销后重新结转
- **付款金额可为负数**：负数表示退款，在表格中以红色标注
- **结转与记账独立**：转结操作不影响"记账"标签页中的手动记账记录

### 7.2 操作限制

- **全部结转不可撤销提示**：系统会提示"此操作不可撤销"，但实际上可通过撤销结转单来恢复
- **导入文件格式**：导入结转和1688账单导入使用不同的模板，请勿混用
- **日期范围影响**：1688账单明细区域的日期选择器仅影响账单明细数据，不影响采购付款明细

### 7.3 数据安全

- 所有结转操作都会记录操作人和操作时间
- 结转单支持完整的撤销和回溯机制
- 建议在大批量结转前先进行小批量测试

### 7.4 使用建议

1. **定期结转**：建议按月或按1688账单周期定期执行结转，避免数据积压
2. **先导入再结转**：建议先导入1688账单明细，再执行结转操作，以便系统更好地匹配数据
3. **核对后再全部结转**：使用"全部结转"前，建议先检查筛选结果是否符合预期
4. **善用筛选条件**：通过仓库、供应商、费用类型等筛选条件，可以更精确地控制结转范围
